# 故障排查

## 根目录显示 Server Working

这是 `:30004/` 服务状态页，不是登录表单。运行 `python3 campus-net-fix.py --apply --open` 获取完整 BYOD 链接，不要只保留域名和端口。不要长期收藏包含某次 IP 的完整链接。

## Chrome 仍打不开，但终端返回 HTTP 200

将脚本输出的完整链接复制到 Chrome 地址栏，确认保留 `http://`。若仍失败，记录准确的浏览器错误代码。检查 Chrome 代理扩展和代理软件，暂时关闭代理 TUN 后对比测试；脚本不会自动更改代理配置。HTTP 200 仅说明 HTTP 请求得到响应，不证明浏览器页面中的所有脚本、API 和后续跳转均成功。

## 重新插线后又无法登录

运行以下命令查看最新地址、网关与认证路由，然后重新应用补丁：

```bash
python3 campus-net-fix.py --status
python3 campus-net-fix.py --apply --open
```

如果脚本提示路由依然没有走有线接口，检查更高优先级的策略路由。脚本不修改复杂路由或代理规则。

## 没有 IPv4 地址或持续出现 IP 冲突

这是补丁的前置条件未满足。先查看：

```bash
nmcli device status
ip -br address
journalctl -b -u NetworkManager --no-pager -n 100
```

提供日志时可遮盖 MAC 和其他设备地址。不要仅凭特殊 MAC 就认定真实地址被他人占用。补丁不会关闭冲突检测或改成任意静态 IP；需要进一步检查 DHCP、ARP、网络侧接入处理。

## Portal 提示设备信息获取失败 / req-info 无回应

先通过脚本获取带当前 IP/MAC 的认证入口。若完整入口仍报同样错误，需要结合当时的 IP、网关、路由和错误页面继续排查，必要时联系学校网络服务人员。该错误不能单凭页面就归因于网卡驱动。

## 是否已经真正连上校园网

完成认证后，暂时停用手机 USB 网络共享与代理 TUN，再测试普通网页。失败时可重新开启共享恢复临时上网。`connected`、出现登录结果页、认证页返回 HTTP 200，均不单独等于校园网互联网访问已成功。

## 撤销为什么没有删除聊天此前添加的路由

`--undo` 只撤销有状态记录的脚本操作，不接管未修改的既有路由。手动清理说明见 [USAGE.md](USAGE.md)。不要删除整个有线连接或其他路由来尝试清理。
