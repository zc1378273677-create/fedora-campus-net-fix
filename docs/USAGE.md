# Fedora 校园网认证补丁

适用：Fedora + NetworkManager，默认针对北京理工大学珠海校区这次连接中发现的认证地址。它修复认证服务器被代理 TUN 接管的问题，并生成随当前 IP 更新的认证入口。它不是学校官方补丁，也不能修复所有校园网故障。

## 运行

将 `campus-net-fix.py` 保存在本机，用普通用户的终端进入文件所在文件夹，然后运行：

```bash
python3 campus-net-fix.py --apply --open
```

默认自动选择已经插线的 PCI 有线网卡。如果无法唯一识别，使用：

```bash
python3 campus-net-fix.py --apply --interface enp2s0 --open
```

无需输入校园网密码到终端。脚本调用系统默认浏览器；只在校园网登录页面输入账号密码。通常无需 sudo；如果 NetworkManager 提示权限不足，请在本机桌面终端运行并按系统提示授权。

认证路由保存到当前 NetworkManager 连接中，重连后仍生效。脚本会实时重新应用连接参数，可能触发有线 DHCP 续租。它不会修改手机 USB 共享连接。自动获取登录入口时，只发送一次普通 HTTP 请求，不执行返回的 JavaScript。

登录成功后，暂时关闭手机 USB 网络共享和代理 TUN，测试普通网页，才能确认有线校园网能独立上网。如果关闭手机后无法上网，可以重新开启共享，再继续排查。

## 检查与撤销

只读检查：

```bash
python3 campus-net-fix.py --status
```

撤销本脚本添加的持久路由：

```bash
python3 campus-net-fix.py --undo
```

路由操作记录保存在 `${XDG_STATE_HOME:-~/.local/state}/campus-net-fix/routes.json`。请使用同一普通用户运行和撤销；保留此文件直到撤销完成。已有相同目标且网关正确的路由会保留。若只有一条没有额外属性的认证主机路由且网关已过期，脚本会更新它，并记录原路由以便撤销。复杂路由不会自动改写。

本次聊天已将认证路由更新为 `10.7.0.103/32 via 10.111.176.1`。如果脚本未改动这条已有路由，它不会被脚本的 `--undo` 删除。若要删除聊天添加的这条路由，可执行（若网关再次变化，先用 `nmcli -g ipv4.routes connection show "有线连接 1"` 查询实际值）：

```bash
nmcli connection modify '有线连接 1' -ipv4.routes '10.7.0.103/32 10.111.176.1'
nmcli device reapply enp2s0
```

## 适用边界

- 有线网卡需已取得 IPv4 地址和网关；没有地址时，脚本停止，不会编造静态 IP。
- 默认先为 `10.7.0.103` 添加经有线网关的单主机路由，再尝试读取网络实际返回的认证入口。
- 自动探测失败时，仅对默认的北理工珠海地址，按本次已验证的 `30004/byod/` 格式生成备用入口。学校更改认证系统后，这个备用格式可能失效。
- IP 地址或网关变化后，请重新运行脚本；它不会在后台自动更新网关。它不会设置开机任务或常驻服务。
- 不会关闭 IP 冲突检测、防火墙，不会更改 MAC、安装或替换驱动。
- 网络持续报告 IP 冲突、认证服务器与接入设备通信失败等问题，仍需进一步排查。仅添加路由不保证解决这些问题。
- 其他学校可以用 `--portal-ip` 指定服务器，但脚本只通用处理路由和 HTTP 认证入口发现，不保证兼容其他认证方式：

```bash
python3 campus-net-fix.py --apply --interface enp2s0 --portal-ip 10.0.0.1 --open
```

已离线验证入口解析、路由记录、重复运行、DHCP 网关变化更新与撤销还原逻辑，以及命令行帮助。此前在本机实测：认证服务器专用路由生效，PCI 网卡能够与服务器双向通信，校园网返回带当前 IP/MAC 的 BYOD 入口。更新后的脚本已在本机运行，确认路由走当前有线网关，认证入口返回 HTTP 200；Chrome 显示结果和校园网独立上网仍需用户验证。
