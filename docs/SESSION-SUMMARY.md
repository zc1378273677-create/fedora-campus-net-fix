# 对话与排查归纳

日期：2026-10-29（北京时间）。本文按问题和结论整理，不是逐字聊天记录。

## 1. 初始问题

用户在 Fedora Linux 上，通过手机 USB 共享网络可以上网，但 PCI 有线网卡无法使用校园网。同一台设备在 Windows 下能够正常接入。学校为北京理工大学珠海校区，用户通常访问 `http://10.7.0.103:9092/portal/` 输入校园网账号密码。

## 2. 本机检查得到的事实

| 项目 | 观察 |
| --- | --- |
| 系统 | Fedora 44 |
| PCI 网卡 | Realtek RTL8111/8168/8211/8411 系列，使用 `r8169` 驱动 |
| 有线接口 | `enp2s0`，对应连接为“有线连接 1” |
| 物理链路 | 接通，内核已识别网卡 |
| 临时上网方式 | 手机 USB 共享连接 |
| 代理 | 存在 `Meta` TUN 虚拟网卡及策略路由 |
| DHCP | 曾获取多个校园网 IPv4，租约约 60 秒；地址和网关后来变化 |

这些事实不支持直接将原因归为缺少网卡驱动，因此没有安装替代驱动或改变 MAC。

## 3. IP 冲突日志

NetworkManager 反复报告 DHCP 分配的地址与 `00:00:00:00:00:01` 冲突，某些时刻网卡没有有效 IPv4。邻居表显示，校园网网关也使用这个 MAC；抓包还能看到该 MAC 发送 ARP 流量。

这不是“另一台普通电脑占用同一 IP”的充分证据，也不能据此确认校园网设备故障。网关代理 ARP、认证接入处理等仅属于待排查方向；本次没有确诊其根因。补丁没有关闭 IP 冲突检测，也没有用静态 IP 绕开 DHCP。

## 4. 认证服务器路由被代理接管

检查 `ip route get 10.7.0.103` 时，发现流量被导向 Meta 虚拟接口。随后为认证服务器添加经有线网关的 `/32` 专用路由，让认证流量使用 PCI 网卡。

手机 USB 共享连接没有被修改。

## 5. 旧 Portal 页面报错与抓包

用户打开旧的 `9092/portal/` 入口，页面提示：

> Portal服务器获取不到设备信息或者设备没有回应req-info报文

用户在本机终端执行了限时 `tcpdump`，并提供输出。抓包可见本机与 `10.7.0.103:9092` 完成 TCP 握手，且有双向数据传输，说明当时认证服务器的 TCP 连接已经可达。

页面错误发生在服务器处理认证信息的阶段，但抓包本身没有确认服务器与接入设备间报文的具体失败原因。

## 6. 发现当前 BYOD 入口

通过有线网卡访问普通 HTTP 地址时，校园网返回了指向以下格式的引导页：

```text
http://10.7.0.103:30004/byod/index.html?usermac=<当前MAC>&userip=<当前IPv4>&...
```

该入口返回 HTTP 200，浏览器后续到达 BYOD 登录及结果页面。仅凭页面 URL 不能断定账号认证和互联网连通性均成功。

直接访问旧 Portal 根入口，可能未包含当前接入所需参数；这是结合新入口作出的解释，而非服务器根因已确诊。

## 7. 用户要求可重复使用的补丁

生成 Python 标准库脚本，提供自动识别有线接口、获取当前 IP 和网关、添加认证路由、探测认证入口、生成北理工珠海备用 BYOD 链接，以及撤销修改的功能。

脚本不会收集校园网密码，不自动登录，也不会部署后台服务。

## 8. 后续发现 DHCP 更换了网段

后续检查发现，DHCP 从 `10.110.0.0/21` 网段换到了 `10.111.176.0/21` 网段，网关也从 `10.110.0.1` 变为 `10.111.176.1`，而此前的专用路由仍引用旧网关。

已更新本机路由，并改进脚本：再次运行时可以更新格式简单的过期认证主机路由。脚本仍需手动重跑；不会自动监听 DHCP 变化。

本次曾出现的地址只是观察记录，不是建议固定使用的配置。

## 9. 用户说 Chrome 无法进入 30004 地址

本机 HTTP 检查表明：

- `http://10.7.0.103:30004/` 返回 `Server Working.`，是服务状态页。
- 完整 `/byod/index.html` 入口返回 HTTP 200。
- 本机认证路由已使用当时的新网关。

已提供包含当前参数的完整链接，并说明需在 Chrome 使用 `http://`。本次无法通过浏览器工具直接检查 Chrome，所以不能声称 Chrome 显示问题已经得到完整验证。

## 10. 交付与剩余边界

交付源码 ZIP、README、操作说明、排查归纳、变更记录及离线测试。

目前已验证认证路由和入口 HTTP 可达性；原有 IP 冲突日志的根因、最终账号认证结果，以及关闭 USB 共享和代理后的独立上网能力，未在对话中得到完整确认。其他学校的专用客户端、802.1X 等认证方式不在此补丁的保证范围内。
